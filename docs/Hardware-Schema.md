# Hardware profiles

Logical vehicle: differential drive, two channels. 2WD maps one motor per side. 4WD groups front/rear motors on each side; firmware may distribute each logical side output. Combined current and driver thermal limits must be checked before parallel motors are connected.

Supported driver profile identifiers are `tb6612fng` and `l298n`. They have distinct electrical characteristics and output-disable wiring. Firmware accepts no default pin map. The initial validator targets ESP32 DevKit/WROOM output GPIOs 4, 13, 14, 16–19, 21–23, 25–27, 32–33 and rejects duplicates, input-only, flash, UART and strapping pins. This whitelist must be revisited if the selected module differs.

The on-device profile includes driver, 2WD/4WD logical grouping, independent A/B direction and PWM pins, TB6612 STBY (required only for TB6612), PWM frequency/resolution/maximum/minimum, steering sensitivity, acceleration/deceleration ramp times, channel inversion, and a nonzero user-verified combined-current limit. Ramps default to zero (no shaping); STOP and watchdog bypass them. A nonzero current entry is only an explicit setup gate; firmware cannot verify motor stall current, supply, parallel wiring, driver cooling or the rating itself. In 4WD, the left pair and right pair are grouped channels; parallel motor connections require checking each pair's combined startup/stall current against driver and supply limits. Independent four-motor control is not implemented.

Use the local USB serial provisioning JSON described in `docs/ESP32-Integration.md`. Invalid or absent configuration leaves motor outputs disabled and prevents arm. A profile-valid NVS marker is committed only after all configuration fields write successfully; absent marker means the profile must be provisioned again. Do not copy sample GPIO values into a real vehicle without checking the exact board schematic and wiring.
