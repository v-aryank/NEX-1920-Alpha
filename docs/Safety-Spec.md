# Safety requirements

Emergency stop immediately requests STOP and requires explicit arm again before driving. Firmware starts disarmed, latches stop through disconnect/reconnect, rejects movement before arm, and disarms/neutralizes on disconnect or after 500 ms without a valid drive command. Heartbeat is not a movement watchdog refresh. The current watchdog tick runs in the Arduino/WebSocket main loop; it does not protect against a stalled CPU/event loop. A separate hardware watchdog or external output-disable mechanism must be evaluated for the target vehicle. Firmware uses TB6612 STBY or zero L298 enable PWM as output disable. No acceleration ramp delays emergency stop. Reconnection never restores throttle.

Frontend sends neutral on input release and STOP on control-session exit, hidden page, mode change and explicit emergency stop; it remains locked unless arm is acknowledged. Malformed messages, unsupported protocol versions, missing fields, out-of-range values, stale sequences and a second control client are rejected by firmware. App checks supplement, not replace, the watchdog. Firmware compiled/runtime watchdog checks do not prove motor driver wiring or physical stopping. Use a separate physical power disconnect during hardware testing. See `docs/Testing-Plan.md` before powering motors.
